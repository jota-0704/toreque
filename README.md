# トレクエ Ver.1

## Supabase接続の設定
supabase-config.jsの`publishableKey: ''`の引用符の中に、Supabase管理画面のPublishable key（`sb_publishable_`で始まる値）を貼り、保存してください。Project URLは設定済みです。Secret keyやservice_role keyは書かないでください。

supabase-client.jsは公式ブラウザ向けCDNのSDK 2.117.2を非同期で読み込み、Clientを1つ生成します。キー未設定・読み込み失敗時もゲームは通常通り動きます。認証セッションはSDK標準機能で保存・自動更新し、メール確認URLもSDKが検出します。クラウド同期は別ファイルcloud-save.jsが担当します。

## アカウント（Supabase Auth）
MENU → アカウントから、メールアドレスとパスワードで新規登録・ログインできます。ログイン中はメールアドレス・ログアウトボタン・クラウド保存状態を表示します。ログインは任意で、ゲームは必ず先にlocalStorageへ保存します。ログイン中はユーザー専用の保存先へ切り替わります。トレーニング・クリア演出中は切り替え操作を止め、外部から認証が変わった場合も終了後に切り替えます。

メール確認のテストは、VS CodeのLive ServerなどでHTTP表示して行ってください。Supabase管理画面のAuthentication → URL Configurationで、Site URLとRedirect URLsに実際の表示URLを設定してください。例：`http://127.0.0.1:5500/outputs/toreque/index.html`（開き方によってパス・ポートは異なります）。登録時は現在ページのURLをメール確認後の戻り先として送信します。file://で開いた場合はSite URLへ戻るため、HTTP表示を推奨します。表示方法を変えるとブラウザの保存領域も変わるので、既存データは元の表示方法のブラウザ領域に残ります。

1. 新規登録へ切り替え、受信できるメールアドレスとパスワードを入力して送信します。
2. Confirm emailがONなら、確認メールの案内が表示され、ログイン済みにはなりません。受信メールのリンクを開き、登録を完了します。
3. MENU → アカウントでログイン状態を確認します。別ブラウザでメールを開いた場合は、元のページでログインしてください。
4. ログイン時は登録した情報を入力します。誤ったパスワード、未確認メールの場合は日本語のエラー案内を確認してください。
5. ログアウトし、未ログイン表示に戻ることと、ゲームの進行・XPが残ることを確認します。ログアウトは現在のブラウザのセッションを対象にします。
6. ログイン後にページを再読み込みして、ログイン状態が保持されることを確認します。
7. Supabase管理画面のAuthentication → Usersで、登録したメールアドレスとメール確認状態を確認できます。

認証コードはauth.jsにまとめています。コンソールの`TorequeAuth.getState()`でもログイン状態とユーザーIDを確認できます。SDK標準の`sb-…-auth-token`キーはゲームデータと別です。Secret keyやservice_role keyは使用しません。

## クラウドセーブ
保存先はpublic.user_progressです。dataには`{ schemaVersion: 1, save: セーブ全体 }`を保存します。認証情報は含めず、サウンドは端末設定として残します。

- 未ログイン：従来の`toreque.v1.setup`。
- ログイン中：`toreque.v1.setup.user.ユーザーID`。
- 同期の比較用情報：ユーザー専用キーの末尾に`.sync`。
- 置き換え前のバックアップ：ユーザー専用キーの末尾に`.backup.日時.識別子`。選択前の端末・クラウドデータを保存します。

まず端末へ保存し、約350ms後に非同期で同期します。通信は直列化し、取得エラーを「クラウドなし」と扱いません。初回作成はINSERT、更新はユーザーIDと取得済みupdated_atを条件にUPDATEします。サーバー側のupdated_at自動更新トリガーとRLSが必要です。同期失敗・競合・認証切り替えでは、古い通信結果を端末へ適用しません。

初回はMENU → アカウントで引き継ぎを選びます。許可するまで未ログインの冒険を送信しません。「引き継がず新しい冒険を始める」も選べます。元の未ログインセーブは常に残ります。クラウドと端末が異なる場合はLEVEL・XP・DAY数・日時を比較し、どちらを使うか選択します。XPや履歴の自動合算は行いません。同意後に通信が失敗した場合、選択済みのデータは端末に保持します。

クラウド適用は形式検証・バックアップ後、保存通知を止めて行います。ゲームのクリア処理は呼びません。レベルや解放項目の既存補正保存は、その後の通常保存として同期できます。クラウドの形式が不正な場合は、適用も上書きも止めます。

オフラインではユーザー専用の端末データで遊べます。アカウント画面の「今すぐ同期」かオンライン復帰で再試行します。再接続時にもクラウドを確認し、別端末の変更を勝手に上書きしません。初めて使う端末でクラウドをまだ取得できていない場合、以前の冒険は通信が戻るまで読み込めません。

ログアウトでは専用セーブを消さず、元の未ログインセーブへ戻ります。専用データは未ログイン領域へコピーしません。`torequeReset()`は現在使用中のローカルセーブだけをリセットし、クラウドは削除・自動上書きしません。再開時はアカウント画面で使用するデータを確認してください。

### 実環境での確認
1. 未ログインで冒険を進め、Aへログインします。引き継ぎを選ぶ前にuser_progressのA行が作られていないことを確認します。
2. 引き継ぎを許可し、「同期済み」とTable EditorのA行を確認します。data.schemaVersionは1、saveには回答・メニュー・進行・履歴が含まれます。
3. DAYをクリア・評価して、XPとhistoryがクラウドにも保存されることを確認します。再読み込みでも復元し、再プレイで初回報酬を再取得しないことを確認します。
4. ログアウトして元の未ログイン冒険へ戻ること、再ログインでAの冒険へ戻ることを確認します。
5. Bへログインし、勝手にAの冒険が表示・送信されないことを確認します。引き継ぎを断ってBの新しい冒険を作ります。
6. 別ブラウザでもAへログインし、片方で進めて同期します。もう片方の「今すぐ同期」で比較が表示され、選ぶまで上書きされないことを確認します。両方の選択をテストします。
7. 開発者ツールのNetworkをOfflineにし、ゲーム保存が続くことを確認します。Onlineへ戻して再同期し、変更が残ることを確認します。
8. AでログインしたConsoleから、Bの実際のUUIDを使って以下のSELECTを実行します。dataがnullでBの内容が読めないことを確認します。続けてBの行へのUPDATEも結果がnullで、管理画面から見たBの値が変わっていないことを確認します。SQL Editorは管理権限なのでRLSテストの代わりにはなりません。

```js
await TorequeSupabase.client.from('user_progress')
  .select('user_id,data').eq('user_id', 'BのユーザーUUID').maybeSingle()

await TorequeSupabase.client.from('user_progress')
  .update({ updated_at: new Date().toISOString() })
  .eq('user_id', 'BのユーザーUUID').select('user_id').maybeSingle()
```

ローカルの自動テストは通信を模擬して実行しています。実際のRLS・トリガー・認証付き保存は上記手順で確認してください。RLSはユーザー間のアクセスを制限しますが、本人が自分のJSON内のXPを改変することを防ぐ仕組みではありません。

接続確認はページを再読み込み後、F12のConsoleで以下を実行してください（VS CodeのLive ServerなどでHTTP表示すると今後の認証開発にも適しています）。

```js
await TorequeSupabase.checkConnection()
```

`ok: true`なら、公開設定取得APIへの接続成功です。テーブル・RLSの動作確認ではありません。`TorequeSupabase.getStatus()`はSDK準備状態、`TorequeSupabase.client`は将来使う共通Clientです。キー未設定では`missing-key`を返します。CDNが失敗した場合は通信環境を確認して再読み込みしてください。

プロジェクト直下の.gitignoreで.envと.env.*を除外しています。.envファイルは今回使用しません。公開設定ファイルはブラウザから見えるので秘密情報を入れないでください。すでにGit管理されているファイルは.gitignoreだけでは除外されません。

## ファイル
- index.html：共通ヘッダーと画面の土台。
- styles.css：赤・白・濃いグレーのデザイン、スマホ・PC対応。
- app.js：各画面の表示と遷移、生成結果の保存・旧データの移行。
- training.js：種目データ、回答からのメニュー生成、時間計算。
- stages.js：ステージの種類・タイトル・前提ステージ・実装状態。
- progress.js：DAYごとの完了・評価履歴、XP、USER LEVEL、連続日数、解放状態。
- workout.js：セット進行、自動遷移、タイマー、一時停止、途中終了確認、COMPLETE画面。
- sound.js：Web Audio APIによる電子音、WORKOUT SOUNDのON/OFF保存。
- storage.js：localStorageへの保存・読み込み・リセット。
- auth.js：登録・ログイン・ログアウトとアカウント画面。
- cloud-save.js：ユーザー別の同期、引き継ぎ確認、競合解決、バックアップ。
- supabase-config.js / supabase-client.js：公開接続設定と共通Client。
- images/logo.svg：仮ロゴ。独自デザインのTマークです。

## Ver.1の範囲
最初はDAY 1のみ解放され、順にDAY 2「もう一歩、前へ」、DAY 3「積み重ねが、力になる」が解放されます。すべて共通の詳細画面と実行処理を使います。
各種目カードを押すとやり方とPOINTを確認できます。説明は「説明を閉じる」またはEscで閉じられます。
「トレーニング開始」から、生成された順番で全種目・全セットを進められます。
回数制は自分で回数を行い「セット完了」を押します。休憩・次セットへの移動は自動です。
時間制は内容を2秒表示してから3・2・1、START!を表示し、自動計測します。
時間制の終了時はSET CLEAR!を短く表示し、自動で休憩や種目終了へ進みます。
左右各の時間制種目は片側ずつ、反対側でも準備時間と3・2・1を挟みます。
セット間は保存済みの休憩秒数で自動計測します。スキップも可能です。
休憩終了後はNEXT SET!を短く表示し、自動で次セットへ進みます。
種目終了後はCLEARを1.5秒表示します。次の種目があれば45秒の種目間休憩を入れ、次の種目名と残り秒数を表示して自動で進みます。最後の種目後は休憩を挟みません。
全種目終了後のCOMPLETEで3段階評価を選び、報酬・解放画面の「ホームへ」で戻ります。
「一時停止」でタイマーと自動進行を停止できます。「再開」で残り時間から再開します。
実行中も「やり方を見る」で説明を確認できます。説明と途中終了確認を開いている間はタイマーが一時停止します。
×またはヘッダーのロゴを押すと途中終了を確認します。「トレーニングを続ける」またはEscで戻れます。
画面再読み込み時はブラウザの確認を表示します。実行途中の進捗は保存しないため、再読み込みするとセット進行はリセットされます。
種目データ・生成ルールはtraining.jsで変更できます。
DAY 3初回クリアでCHECK POINTを解放します。成長記録を確認するとチャプターが完了し、DAY 4「新しい挑戦」を解放します。
完了しても保存済みの回答・DAY 1メニュー・部位別内部レベルは変更しません。

## クリア履歴と報酬
通常DAYはそれぞれ初回クリア時だけ100 XP、CHECK POINTは初回確認時だけ150 XPを獲得します。再プレイ・再訪では報酬は付与しません。
USER LEVELはLv.1から開始し、必要XPは500＋（現在レベル−1）×250です。progress.jsのrequiredXpとlevelStateで管理し、余剰XPを次レベルへ持ち越します。上限はありません。
端末のローカル日付で同日の完了は1日分、翌日は連続加算、1日空いた場合の次回は1日から開始します。最後の実施日が一昨日以前ならホームは連続0日を表示します。
完了直後にXP・クリア・日時・連続日数を保存し、その後の評価を履歴へ保存します。
評価前にページを更新した場合、「つづける」から未入力の評価に戻ります。報酬は重複して付与しません。
評価はtooHard/justRight/easyとしてprogress.history[DAY番号].runsに記録し、初回日時・最新日時・初回評価・最新評価も持ちます。
既存ユーザーには不足する進行項目を安全な初期値で補います。回答のやり直しは不要です。
torequeReset()は回答、メニュー、XP、履歴、レベル、連続日数、解放をまとめて削除します。サウンド設定は維持します。

## DAY 2のメニュー
DAY 1と同じ生成ルールを共通利用し、DAY 1未使用の種目を選びやすくします。重点部位は引き続き約半分です。
候補が限られ同じ並びになった場合は順番を変えます。目的と安全な難易度の範囲は維持します。
評価による負荷変更は下記「評価履歴による負荷調整」のルールを使います。セット数・休憩も含めて時間上限を調整します。
DAY 2生成結果はdayTwoとして保存し、再読み込みやDAY 1再プレイで勝手に変更しません。部位別内部レベルは一括変更しません。
DAY番号とメニューを共通の詳細画面・実行システムへ渡し、DAY 2も最後まで実行できます。

## DAY 2の確認
DAY 1を最後まで実施して評価を選択し、DAY 2 UNLOCKとLv.1・100 / 500 XPを確認します。
「ホームへ」→DAY 2→「トレーニング開始」で進めます。DAY 2初回クリア後は累計200 XPでLv.1です。
DAY 1/2の再プレイでXPが増えないこと、更新後もクリア・評価・メニューが残ることを確認してください。

## DAY 3とCHECK POINT
DAY 2の評価後にDAY 3 UNLOCK!を表示します。以前のバージョンでDAY 2クリア済みの場合も、保存済み履歴からDAY 3を解放します。XPや既存メニューを再付与・再生成しません。
DAY 3は初回回答と直近の評価履歴を使います。同程度の難易度の候補から変化をつけ、候補が少ない場合は負荷維持を優先します。重点割合と時間上限は維持します。部位別レベルは変更しません。
生成したDAY 3はmenus[3]に保存します。追加DAYも番号をキーにしたmenusを使う構造です。旧dayOne/dayTwoも互換性のため維持します。
stages.jsのrequiresが前提ステージ、availableが今回の実装状態です。共通の解放計算が前提ステージのクリア履歴を読みます。DAY 4はDAY 3、checkpoint1はDAY 4が前提です。

DAY 2完了・評価→DAY 3→トレーニング開始→完了・評価を確認してください。初回報酬の合計は300 XPでLv.1になります。
DAY 4のクリア後にCHECK POINT UNLOCK!を表示します。ホームの旗のボタンを押すと成長記録を確認できます。
DAY 3再プレイでもXPが増えないこと、ページ更新後もメニュー・履歴・解放状態が残ることを確認できます。
torequeReset()で全進行を削除し、DAY 1から再確認できます。WORKOUT SOUND設定は維持します。

## CHECK POINTの内容
TOTAL XP、USER LEVEL、現在の連続日数、DAY 1〜4の完了日数、総セット数、総種目数、各DAYの最新評価を保存データから表示します。
総セット数・総種目数にはDAY 1〜4の完走した再プレイも含みます。完了履歴には実行メニューの件数をruns[].statsとして保存します。
旧履歴に件数がない場合は保存済みメニューから集計します。メニューもない過去記録は集計対象外とし、画面に注意書きを表示します。未記録の評価も表示できます。
評価の多い傾向からルールで短い応援メッセージを表示します。医療判断やAI APIは使いません。

「成長を確認！」でCHAPTER 1 COMPLETE演出へ進みます。初回は150 XPを付与し、通常4日の400 XPと合わせて550 XP・Lv.2・50 / 750 XPになります。次にDAY 5を解放します。
checkpoint1の完了日時・報酬取得済み状態はprogress.history.checkpoint1に保存し、progress.unlockedExercisesと解放状態も保存します。確認だけで運動のセット数・種目数・ストリークは増やしません。
再訪時は記録・評価・解放済み種目を確認できます。確認ボタンを再度押しても150 XPは再付与せず、クリア日時も更新しません。

## 新種目とDAY 4
ワイドプッシュアップ、リバースクランチ、リバースランジはrequiredCheckpoint='checkpoint1'を持ちます。
これから生成するDAY 1〜4では候補から除外します。アップデート以前の保存済みメニューに含まれていても、既存メニューを壊さないためそのまま維持します。
CHECK POINTクリア後のDAY 5以降では候補になります。目的・部位・初期難易度の条件も必要で、3種目を無条件に全採用する仕様ではありません。
DAY 4は初回回答と直近の評価履歴を使い、直前に評価したメニューから小さく負荷を調整します。部位別レベルは一括変更しません。
メニューをmenus[4]に保存し、再訪・再読み込みでは同じものを使います。DAY 5〜11も共通の詳細画面・実行システムを利用します。

DAY 4の評価後→CHECK POINT→記録・評価を確認→「成長を確認！」→150 XP/新種目/DAY 5 UNLOCK→ホーム→DAY 5を確認してください。
CHECK POINT再訪でXPが増えないこと、DAY 4で既存のタイマー・音・一時停止が使えること、更新後も記録と解放が維持されることを確認できます。

## サウンド設定
ヘッダーの「設定」→ WORKOUT SOUNDでON/OFFを変更します。初期値はONです。
短い低めの電子音が3・2・1、長めの高い電子音が開始・終了を示します。
音量は小さめで、外部音声ファイルは使用しません。
設定は専用キーtoreque.v1.soundに保存するため、回答・メニューの保存データに影響しません。
torequeReset()でもサウンドの好みは維持します。
設定画面を開いている間は実行中のタイマーを止めます。手動で一時停止中の場合、設定を閉じても勝手に再開しません。
ブラウザの音声制限を解除するため、トレーニング開始などのクリック時にAudioContextを準備します。音声非対応でも画面は動作します。

## 自動進行の確認
時間制種目が含まれるDAY 1で、開始前3・2・1、終了前3・2・1、休憩終了前3・2・1の音を確認してください。
「一時停止」「再開」、説明・設定・終了確認で残り時間が止まること、OFFで無音になること、再読み込み後もOFFが維持されることを確認できます。

## メニュー生成
- 目的：筋力系・全身運動・健康向けの選択傾向を変更。
- 重点部位：種目数の約半分を重点にし、赤いバッジを表示。全身・特になしはバランス型。
- ジャンプ可否：answers.canJump（true / false）として保存。未設定も静かな運動のみです。旧frequency・週間設定は既存データ互換のため残します。
- 時間：10/20/30/45/60分以上に対して3/4/5/6/6種目。セット数・休憩も調整します。
- 腕立て回数：胸・腕の初期レベル1〜5を決定。他の部位はレベル1から開始します。

メニュー生成の所要時間概算は、1回3秒または時間制種目の秒数、左右の動作、セット間休憩、種目間の準備30秒、準備・整理運動120秒を合計して切り上げます。生成ロジックは変更していません。実行時の種目間休憩は45秒のため、表示時間は目安です。
健康目的は低難易度を優先。胸・腕以外は初回は難易度2以下です。
ブルガリアンスクワットは登録済みですが台が必要なため自動選択しません。
「背中」にはバードドッグなど器具なし種目を追加しています。

保存キーは既存と同じtoreque.v1.setup。answersとcompletedを保持し、dayOne、categoryLevels、weeklyPlanを追加します。既存の回答だけのデータもDAY 1表示時に自動移行します。
生成結果は保存するため、再読み込みしても同じです。部位別レベルはcategoryLevelsに独立して保存し、変更時は再生成できます（変更画面は未実装）。

## 生成の確認
DAY 1を開いて重点バッジ・種目数・目安時間を確認してください。再読み込み後も同じメニューです。
torequeReset()でリセットして別の回答を選ぶと、新しいメニューが生成されます。
開発者ツールでTorequeTraining.generate({...})を使えば保存せずに試せます。

## 評価履歴による負荷調整
すべてのDAYのrunsを完了日時順に読み、再プレイも含めた直近3回から判断します。旧データでrunsがない場合は保存済みの最新評価を利用します。CHECK POINTは含めません。
直近2回を重視し、ちょうどいい→きつすぎたは1回/2秒減、楽だった→きつすぎたは維持、きつすぎたが2回連続なら2回/5秒減です。最新がちょうどいいなら現在の負荷を維持します。
最新が楽だったなら1回/3秒増、前回もちょうどいい・楽だったなら2回/5秒増です。初期基準からの累計ではなく直前メニューを基準にするため、少しずつ調整できます。時間上限では増量を抑えます。
まず回数・秒数を変更します。同じ評価が3回連続し、回数・秒数が上下限に達した場合のみセット数変更を許可し、さらにセット数の限界に達した場合だけ種目難易度の変更を検討します。目的・重点部位・初期難易度の安全範囲は維持します。
保存済みメニューは変更しません。このルールはこれから生成するメニューに適用します。XP・進行・categoryLevels・既存の保存キーは維持します。
開発者ツールで `TorequeTraining.getLoadAdjustment(['justRight', 'tooHard'])` を実行すると、action・reps・seconds・reasonを確認できます。評価は古い順に渡します。`TorequeTraining.feedbackFromSaved(TorequeStorage.read())` で保存済み履歴を確認できます。

## CHAPTER 2と今後のステージ追加
`stages.js`のchaptersが章タイトル、allがステージ定義です。各定義のchapter・type・requires・rewardを共通の表示、解放、報酬処理が読みます。既存の数値DAYキーとcheckpoint1を維持しています。
CHAPTER 1はDAY 1〜4→checkpoint1、CHAPTER 2はDAY 5〜11→checkpoint2です。checkpoint1クリアでDAY 5、DAY 11クリアでcheckpoint2を解放します。すべてのDAYと章末のCHECK POINTをクリアするとCHAPTER COMPLETEになります。
ホームの章ボタンでマップを切り替えます。初期表示は次の未クリアステージの章です。勇者の現在地も同じ定義から判定します。各CHAPTERで既存の敵画像を共通描画します。全章クリア後はFINAL CHECK POINTの先に勇者とQUEST CLEAR!を表示します。
新しいDAYは回答、部位別レベル、直近の評価、解放済み種目から共通生成し、menus[DAY番号]へ保存します。種目の変化には定義順の直近3DAYを使い、評価履歴は再プレイも含めて完了日時順に利用します。既存の保存済みメニューは再生成しません。
通常DAYは初回100 XP、通常CHECK POINTは初回150 XP、FINAL CHECK POINTは初回300 XP。再プレイ・再訪では重複付与しません。checkpoint2はCHAPTER 2のXP、現在のレベル・ストリーク、対象DAYの運動記録と最新評価を共通集計で表示します。
ナロープッシュアップ、サイドプランク、マウンテンクライマーはrequiredCheckpoint='checkpoint2'で管理し、章末ボスのクリア後に解放します。CHAPTER 3・4も実装済みです。旧メニューに既に含まれる種目は維持します。
DAY 11の後に第二のCHECK POINTへ進み、クリア後とホームにCHAPTER 2 COMPLETEを表示します。ストリークルールは維持します。
将来、新しいCHAPTERを追加する際はchaptersの章情報とallのステージ定義を追加し、必要ならtraining.jsの種目・解放条件を追加してください。敵画像はstages.jsの各ステージにenemyを設定します。専用の画面・実行関数は不要です。新しいrequiresは既存のDAY番号またはCHECK POINTのidを指定します。

## 種目間休憩とレベル内XP
セット間は従来のrest/restclear、種目間はexerciseRestという別の状態で管理します。種目間は45秒の自動カウントダウン、最後3秒と終了の既存効果音、一時停止・再開を利用します。最後の種目後は直接完了画面へ進みます。
セット間RESTと種目間RESTの両方にスキップボタンを表示します。セット間は既存のNEXT SET!演出を経て同じ種目の次セットへ、種目間は次の種目へ進みます。既存のcleanupでタイマーと音を停止し、古いコールバックは世代チェックで無効化します。一時停止中はスキップボタンも無効です。
セット間REST後のNEXT SET!は以前の800msに1500msを追加して2300ms表示します。REST自体の時間やカウントダウンの音は変更していません。
通常敵はステージ定義のenemyから表示します。既存のプリセット（slime/goblin/orc）か、`enemy: { image: 'new-enemy.png', name: '新しい敵', size: 'goblin' }`を指定できます。新画像をimagesフォルダへ置けば共通描画で表示され、ロック・クリア時の表示も共通で適用されます。ボスはCHECK POINTのbossImageに指定します。

## 章末のボス配置と既存履歴
筋肉の魔王は通常DAYのenemyではなく、CHECK POINTのbossImageとbossNameで指定します。各章のCHECK POINTは1つだけなので、その章のマップに1体だけ表示します。ボスはボタンの真上の専用領域に配置し、ロック時は暗く、クリア済みなら薄く小さく表示します。
旧配置で途中のCHECK POINTを既にクリアしていても、履歴・XP・種目解放・メニューは削除しません。クリア済みステージは再訪でき、未クリアステージは新しい前提経路をすべて確認して解放します。例えば旧checkpoint1クリア済みでもDAY 4未クリアなら、勇者はDAY 4に表示されます。
章の進捗は通常DAYだけを数えて「4 / 4 DAY CLEAR」「7 / 7 DAY CLEAR」と表示します。その後、章末ボスをクリアした時点でCHAPTER COMPLETEになります。
保存済みprogress.xpは累計XPのまま維持します。levelXpは現在のレベル内XP、requiredXpは次のレベルへの必要XPです。読み込み時に累計XPから再計算し、旧データの履歴・回答・メニュー・ストリークは保持します。
例：累計500 XPはLv.2・0 / 750 XP、550 XPはLv.2・50 / 750 XP、2350 XPはLv.4・100 / 1250 XPです。ホームはレベル内XP、CHECK POINTのTOTAL XPは累計を表示します。
レベルアップ時はLEVEL UP!と前後のレベル、持ち越したXPを表示します。報酬取得後に評価待ちで閉じた旧データも、新ルールで結果画面を復元し、XPを再付与しません。

## CHAPTER 3・4 / V1の完結
- `stages.js` の定義でDAY12〜18 → CHECK POINT 3 → DAY19〜25 → FINAL CHECK POINTを追加。トレーニング・評価・RESTは共通処理です。
- ボスはCH1筋肉の魔王、CH2鉄壁のマッスルナイト、CH3マッスルドラゴン、CH4真・筋肉の魔王。各章のCHECK POINTだけに表示します。
- CHECK POINT 3でパイクプッシュアップ、レッグレイズ、ハイニーを解放。保存済みメニューは維持し、以後の新規生成候補に加わります。
- FINAL CHECK POINTは冒険全体を集計し、初回のみ300 XP。QUEST CLEAR後もすべてのクリア済みDAYを再プレイできます。
- 保存キー・TOTAL XP・履歴・メニューを初期化しません。CHAPTER 2クリア済みならDAY12へ続きます。

## ジャンプ系運動の設定
初回Q3は「ジャンプする運動はできる？」です。SETTINGの「ジャンプ系運動」ON/OFFでも変更できます。未設定はOFF相当で、初期化や回答のやり直しは不要です。
種目のrequiresJump属性を共通生成で判定します。ジャンピングジャックはtrue、代替ステップジャックはfalseです。現在のハイニーは跳ばない足踏み、マウンテンクライマーはゆっくり交互に動かす仕様、バーピーは跳ばない仕様のためfalseです。
すべてのDAYの新規生成に適用し、既存キャッシュも必要なら静かな種目へ置き換えたコピーを使います。元のメニュー履歴・XP・クリア・評価記録は削除しません。実行中のメニューは変えず、次の開始から設定を反映します。

## CHAPTER撃破演出・最終エンディング
初回CHECK POINT確認時は、従来のcompleteCheckpointで報酬を一度保存してから表示演出へ進みます。演出中・エンディング再生中は報酬処理を呼びません。
- CHAPTER 1〜3：ボス撃破2.4秒 → BOSS DEFEATED! 0.9秒 → CHAPTER COMPLETE。解放種目はstages.jsとcatalogから取り出し、0.45秒間隔で表示。「次のCHAPTERへ」で次章のマップへ戻ります。
- FINAL：撃破3.2秒 → 静かな余韻1秒 → FINAL QUEST COMPLETE 0.9秒 → QUEST CLEARと初心者編エンディング。
- 最終画面のYOUR JOURNEYはクリア履歴とボス定義、冒険の記録は保存済みのXP・レベル・DAY・運動回数・ストリーク・セット・種目数を集計。未保存の種目/セット記録は推測で補いません。
- ファンファーレはsound.jsのWeb Audio APIで約1.4秒の旋律。WORKOUT SOUND OFFでは無音。予約音も既存silenceで停止できます。
- 再訪は演出を強制せず結果画面へ。「エンディングをもう一度見る」は表示・音だけを再生します。
- 演出タイマーは1本、画面変更時に解除しトークンで古いコールバックも無効化。演出中はヘッダー操作を無効にし、確認ボタン連打もガードします。
- prefers-reduced-motionでは揺れ・移動・フラッシュ・紙吹雪を省き、重要なメッセージと操作は残します。

## 一時的な開発用即クリア（DEV ONLY）
`app.js`冒頭の `const DEV_MODE = true;` が表示スイッチです。公開前は `false` にして再読み込みすると、すべてのDEVボタンがHTMLからなくなります。
- DAY詳細から「トレーニング開始」後、画面下の「DEV：このDAYを即クリア」で全セット実施相当の記録を渡し、既存のenter('complete')へ進みます。通常の評価を選ぶと次のステージを確認できます。
- CHECK POINTの「DEV：CHECK POINTを即クリア」、FINALの「DEV：FINAL BOSSを即クリア」は通常の確認ボタンと同じ処理です。報酬・解放・ボス撃破・エンディングは共通経路です。
- 特別なXP処理や保存キーは追加していません。テスト結果も通常の進行・運動記録として保存します。再プレイでは初回XPを取得できません。
- DEV_ONLYのコメントとdev-clear-buttonクラスが削除箇所の目印です。

## MENU・トレーニング図鑑
ヘッダーの「☰ MENU」から図鑑・遊び方・冒険の記録・設定・アプリ紹介を開けます。menu.jsは情報表示のみを担当し、開いているゲーム画面は保持します。ワークアウト中は既存のモーダル一時停止を使い、MENUと設定を閉じた後に再開します。マップへ戻る際は既存の終了確認を表示します。
図鑑はtraining.jsの30種目をカテゴリ別に表示し、IDから同じhow・point・caution・画像対応を参照します。未解放種目も説明を読めますが、ステージや生成候補の解放条件は変更しません。
画像は各種目のimage（images/種目ID.jpeg）で参照します。単独画像全体を幅100%・高さautoで表示し、縦横比を維持します。以前の6分割コードは廃止しました。リネームのみでJPEGを再圧縮していません。元ファイル名との対応はimage-mapping.mdを参照してください。
冒険の記録とFINAL CLEARはTorequeProgress.adventureSummaryとadventureRecordsHtmlを共通利用します。計算方法は従来と同じです。設定も既存の保存処理を再利用します。
